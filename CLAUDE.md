# CLAUDE.md — Engineering Data Integration Accelerator

You are implementing a reusable **accelerator for engineering data integration projects**.
The product is specified in `docs/prd/` (start from `docs/prd/00-index.md`). Architectural
decisions live in `docs/adr/`, contracts in `docs/specs/`. The current increment is in `docs/backlog/`.

Read those before proposing anything. When the code and the PRD disagree, stop and ask.

## What the platform does — and only this

1. **Connect** tools without copying their data (stable identity, navigable links).
2. **Remember** the state of relationships over time (rebuildable from events).
3. **Enforce** authority, maturity and configuration rules deterministically.

Guiding principle: **federate the truth, materialise the questions.**

## Non-negotiable rules (violating one is a bug, not a trade-off)

- The source tool is authoritative. The graph is a **derived projection**: never write into
  it data that does not exist in a source tool or in an event.
- The graph must be **fully rebuildable** by replaying the event log. Any feature that
  breaks `rebuild → identical graph` is rejected. (FR-M03, AD-01)
- URIs are **opaque and stable**: random identifiers minted by the Resolver, **never**
  derived from part numbers, names, paths or any mutable attribute. (AD-03)
- Every assertion in the graph carries **PROV-O provenance** (source, event, time). (FR-M02)
- Link states: `proposed → asserted → validated`, plus `superseded` and `dangling`.
  *Asserted* = confirmed in the system that owns the relationship. *Validated* = asserted
  and SHACL-conformant. Never use the word "verified" for a link state. (AD-06, AD-10)
- Platform-owned state (URIs, link states, dispositions, adapter cursors) lives in PostgreSQL and every
  change is also emitted as an event via the outbox, so a rebuild reproduces it. (ADR-0016)
- Use only standard SPARQL 1.1 and SHACL: no vendor-specific features. (ADR-0015)
- A new version of an input never deletes what depends on it: dependent links become
  `superseded` and a disposition is opened for their owner. Before configuration control
  this is the only regime; after release, changes go through the PLM Change. (FR-S14,
  FR-S15, FR-G17)
- Desktop tools (MATLAB, Simulink, OpenModelica, Excel) never get a live adapter: they
  integrate only through the publication kit. (ADR-0017)
- Publication inputs are read from the platform with their version; typed values are never
  accepted as lineage. Excel is publishable only from a registered controlled template.
  (FR-G19, FR-G20)
- Contracts live in `docs/specs/` (envelope shape, reason codes); change them only via ADR.
- Deleted targets make links `dangling`; links are never silently deleted. (FR-F06, FR-S07)
- Degrade **explicitly**: if a source is unavailable, results are marked partial with data
  age; never return silently incomplete data. (FR-A10, FR-M08)
- Always keep the **native value and unit** next to any normalised value. (FR-T04)
- AI features are out of scope until the backlog says otherwise. Nothing generated by a
  model may ever become `asserted` without human approval. (FR-S06, AD-11)
- Everything that varies between programmes is **configuration, not code**: tool
  registrations, state names, maturity scales, shapes, units. No programme-specific
  `if` statements in the runtime. (AD-12)

## How we work

- **Plan before code.** For any story, first write a short plan (files, tests, risks) and
  wait for approval unless told to proceed.
- **One story at a time**, as a vertical slice, with tests. Reference the FR/AD IDs the
  story implements in test names or comments (e.g. `// FR-S07`).
- **Tests use fixtures only** (`fixtures/skid400`, `fixtures/aero7`). Never call a real
  Teamcenter, Polarion or any customer system. Simulators live in `simulators/`.
- A decision not covered by an ADR → write a new ADR in `docs/adr/` with status
  `Proposed` and ask for review. Do not bury decisions in code.
- Keep this file current: when a build/test command changes, update **Commands** below.
- Commit messages: `<story-id>: <what>` (e.g. `S04: TRS polling to CloudEvents`).

## Stack (proposed — see docs/adr/0015-walking-skeleton-stack.md)

Java 21 · Maven multi-module · Spring Boot · Eclipse Lyo OSLC4J · Apache Jena (RDF, SHACL)
· Jena Fuseki (GraphDB Enterprise as production option) · Kafka (KRaft) + CloudEvents · PostgreSQL · JUnit 5 + Testcontainers
· Docker Compose for local runs. Until ADR-0015 is `Accepted`, confirm before adding
dependencies outside this list. Pin every dependency version.
Publication kit (client side only): Python — see ADR-0017, once accepted.

## Commands

Prerequisites: a container runtime with a Compose provider (Docker Desktop, or Podman
with `podman compose` delegating to `docker-compose`). JDK 21 and Maven are **not**
required on the host — `make verify` runs Maven inside a container.

- `make verify` — compile and test every module via a pinned
  `maven:3.9.9-eclipse-temurin-21` container. Override with `make verify MVN=./mvnw`
  once JDK 21 is installed locally.
- `make up` / `make down` — start / stop the local stack (Kafka KRaft, Fuseki,
  PostgreSQL). `make down` keeps named volumes.
- `make images` — build an OCI image per service and simulator, tagged with the short
  git SHA and labelled `org.opencontainers.image.revision`. Falls back to `dev` when the
  working tree has no commits.
- `make e2e` — placeholder (story S11).
- `make rebuild-graph` — placeholder (story S06).

Variables that override behaviour: `CONTAINER` (default `podman`), `COMPOSE` (default
`$(CONTAINER) compose`), `JAVA_IMAGE`, `MVN`.

Environment-specific setup (choice of runtime, local JDK, Podman-on-WSL cgroup fix):
see [docs/dev-setup.md](docs/dev-setup.md).

## Glossary (short)

- **Resolver** — maps opaque URIs ↔ native IDs and deep links; handles aliases, tombstones.
- **Link Index** — link metadata only (never artefact content).
- **Integration bus** — mediation + event bus (Kafka). Not to be confused with the
  **PLM backbone**, which is a tool (e.g. Teamcenter) acting as product anchor.
- **Projection** — the graph built from events; **freshness** = age of the projected copy.
